# analyst-skills

Репозиторий навыков (skills) аналитической команды для Claude Code. Каждый участник ведёт свою папку с навыками. Периодически лучшие навыки отбираются в общую папку `shared-skills/`, остальные из личных папок удаляются.

## Структура репозитория

```
<имя>-skills/          личная папка участника, например zlata-skills, andrey-skills, alexandra-skills
  <skill-name>/
    SKILL.md           сам навык

shared-skills/          общие навыки, отобранные из личных папок
  <skill-name>/
    SKILL.md
```

Правила именования: имя папки навыка совпадает с полем `name` в SKILL.md.

## Как добавить свой навык

1. Если у тебя ещё нет своей папки — создать `<твоё-имя>-skills/` в корне репозитория (пример: `zlata-skills`, `ivan-skills`).
2. Внутри создать папку `<имя-навыка>/` и в ней `SKILL.md`.
3. Заполнить frontmatter: `name` и `description`. В `description` написать, когда навык применять, и включить слова-триггеры, по которым модель его подхватит.
4. Держать SKILL.md короче 500 строк.
5. Добавить строку с названием и описанием навыка в таблицу своей папки в разделе «Что внутри» ниже.

## Как навыки попадают в shared-skills

Периодически команда просматривает все личные навыки. Отобранные — переносятся в `shared-skills/` как общий навык команды. Остальные, не прошедшие отбор, удаляются из репозитория.

## Что внутри

### zlata-skills

| Навык | Что делает |
|---|---|
| `russian-final-style` | Русский стиль исследовательских отчетов: тезис в начале абзаца, запрет длинных тире, буквы ё, конструкции «не X, а Y» и нейросетевых усилителей |
| `inline-sources` | Ссылка ставится на утверждении внутри предложения, каждое число помечается как замер, расчет, оценка или допущение |
| `sopostavimost` | Проверка сопоставимости по пяти осям перед любым множителем, процентом разницы или утверждением «X больше Y» |
| `check-before-send` | Обязательная проверка перед выдачей файла с расчетами: воспроизвести производные числа, сверить суммы частей с итогом, назвать свежесть данных |
| `minto-storyline` | Сторилайн как дерево тезисов по Минто, протокол проверки веток на MECE, правила обращения с цифрами, раскладка в 6-pager |
| `zlata-viz` | Графики для отчетов: чистый inline SVG без внешних библиотек, геометрическая проверка подписей кодом |

## Что в репозиторий не кладется

1. Финансовые модели, выгрузки, клиентские данные и любые рабочие файлы проектов. Репозиторий содержит только методологию.
2. Токены, ключи API, ссылки на внутренние системы с доступом.
3. Навыки чужого авторства без разрешения автора и без указания лицензии.
